# Spec：Google 登入（可選）＋ 跑酷分數雲端排行榜

**日期**：2026-07-09
**狀態**：設計中（待使用者確認 + Console 設定後實作）

## 需求

1. **不強迫登入**：預設維持 localStorage 存 HI 分數，一切現有功能不受影響
2. 側欄提供「綁定 Google」入口；綁定後跑酷分數同步到 Firestore
3. **排行榜**要能查：
   - 本週最高分 Top N
   - 歷史最高分 Top N
4. 未登入也可以「看」排行榜，只是不會上榜

## 技術選型

- Firebase Authentication（Google provider）＋ Cloud Firestore
- SDK 用 **compat 版**（classic `<script>`，與現有無 build、全域共享的程式風格一致）
- 免費 Spark 方案即可（每局 game over 至多一次寫入）

## 資料結構（Firestore）

一人一份文件，同時攜帶「本週」與「歷史」兩個榜需要的欄位：

```
scores/{uid}
├── name       : string   // Google displayName（公開顯示，spec 下方有隱私註記）
├── photo      : string   // Google 頭像 URL（排行榜顯示用，可空字串）
├── allTimeHi  : number   // 歷史最高分（只增不減）
├── weekHi     : number   // 「weekId 那一週」的最高分
├── weekId     : string   // 該筆 weekHi 所屬週，格式 = 該週週一日期 "YYYY-MM-DD"
└── updatedAt  : timestamp
```

### 為什麼這樣設計

- **一人一 doc**：排行榜天然去重（每人只出現一次），讀取成本固定（Top10 = 10 reads）
- **weekHi + weekId 取代「每週一份文件」**：
  - 本週榜查詢：`where weekId == 本週一 && orderBy weekHi desc`——weekId 不是本週的人自動落榜，**不需要任何排程去重置**
  - 歷史榜查詢：`orderBy allTimeHi desc`
  - 缺點是不保留過去週的榜單歷史——目前需求只要「本週 + 歷史」，夠用；未來要週榜歷史再加 `weeklyArchive/{weekId}_{uid}`（結構預留，不影響現有欄位）
- **週的定義與 App 一致**：週一 00:00 起算（沿用 updateProgress 既有的 monday 計算），weekId 直接用該週一的 `YYYY-MM-DD`

### 寫入邏輯（client，game over 時）

```
if (未登入) return;                    // 只動 localStorage（現狀）
if (score <= 0) return;
newAllTime = max(score, cloud.allTimeHi)
newWeekHi  = (cloud.weekId == 本週一) ? max(score, cloud.weekHi) : score
若 newAllTime 或 newWeekHi 有變才寫入（省配額）
```

### 首次綁定的本地分數合併

- `allTimeHi = max(localStorage hi, cloud allTimeHi)`——本地舊紀錄不作廢
- `weekHi` **不**吃本地值（無法證明是本週打的），從綁定後的第一局開始累計

## Security Rules

（v2：經 Gemini 3.1 Pro 交叉 review 後修訂——補上「同週分數不可下修」「欄位齊全 hasAll」「name/photo 型別與長度上限」「強制 serverTimestamp」）

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /scores/{uid} {
      allow read: if true;  // 排行榜公開讀
      allow create, update: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.keys().hasAll(['name','photo','allTimeHi','weekHi','weekId','updatedAt'])
        && request.resource.data.keys().hasOnly(['name','photo','allTimeHi','weekHi','weekId','updatedAt'])
        && request.resource.data.name is string
        && request.resource.data.name.size() > 0
        && request.resource.data.name.size() < 50
        && request.resource.data.photo is string
        && request.resource.data.photo.size() < 500      // 防塞 base64 大圖轟炸讀取頻寬
        && request.resource.data.allTimeHi is int
        && request.resource.data.allTimeHi >= 0
        && request.resource.data.allTimeHi < 100000      // 計分顯示上限 5 位數
        && request.resource.data.weekHi is int
        && request.resource.data.weekHi >= 0
        && request.resource.data.weekHi <= request.resource.data.allTimeHi
        && request.resource.data.weekId is string
        && request.resource.data.weekId.size() == 10
        && request.resource.data.updatedAt == request.time   // 強制前端用 serverTimestamp()
        // 歷史最高只能往上走，不能被舊 client 蓋回去
        && (resource == null || request.resource.data.allTimeHi >= resource.data.allTimeHi)
        // 同一週內 weekHi 也不可下修；換週才允許重設
        && (resource == null
            || request.resource.data.weekId != resource.data.weekId
            || request.resource.data.weekHi >= resource.data.weekHi);
      allow delete: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

**已知限制**：
- 純前端無法防「開 console 假造分數」，Rules 只能限制範圍（0～99999、只增不減）。定位是同事朋友間的趣味榜，不是公正競技
- 離線跨週邊緣案例：週日離線玩的分數，週一連網才同步時會被算進新的一週（趣味榜可接受，不處理）

## 查詢與索引

| 榜 | 查詢 | 索引 |
|---|---|---|
| 本週 | `scores where weekId == W orderBy weekHi desc limit 10` | 複合索引 weekId ASC + weekHi DESC（寫進 firestore.indexes.json） |
| 歷史 | `scores orderBy allTimeHi desc limit 10` | 單欄位自動索引，免設定 |

## 隱私註記

- 排行榜會公開顯示名稱與頭像；**綁定入口需明示**「您的名稱與頭像將公開顯示在排行榜上」
- **自訂暱稱（v2 納入）**：`name` 欄位預設取 Google displayName，使用者可透過側欄「✏️ 修改排行榜暱稱」改寫；後續分數寫入會保留自訂值不回退

## 防 XSS（v2 納入，使用者要求：每個前端上傳欄位都要防）

三層防護：
1. **上傳前 sanitize（client）**：`name` 去除 `<>`、trim、截 40 字；`photo` 僅接受 `^https://[^<>"\s]*$` 且 <490 字，否則空字串；分數 clamp 到 0～99999 整數
2. **Security Rules（服務端）**：`name.matches('[^<>]*')` 拒收角括號；`photo` regex 強制 https 格式——繞過前端直打 API 也寫不進髒資料
3. **顯示端（根本防線）**：排行榜渲染一律 `createElement` + `textContent` / DOM property 賦值，禁用 innerHTML 插值；頭像 `img.src` 用 property 賦值並先過 sanitizePhoto

## 實作注意（review 補充）

- 寫入一律用 `set(..., { merge: true })` 搭配完整欄位，`updatedAt` 用 `serverTimestamp()`
- 分數 0 不上傳；未登入狀態不得觸發任何雲端寫入
- 先讀後寫：game over 時先讀自己的 doc 再決定要不要寫，避免無謂寫入與 Rules 拒絕

## 使用者需要在 Firebase Console 做的一次性設定

1. **Authentication → 登入方式 → 啟用 Google**（支援電子郵件需選一個）
2. **Firestore Database → 建立資料庫**：正式版模式，區域建議 `asia-east1`（台灣）
3. Rules 與索引不用手動設——實作時我會寫進 `firestore.rules` / `firestore.indexes.json`，`firebase deploy` 一併發布

## 測試注意

- Google 登入 popup **不能在 `file://` 下運作**，本地測試要起 http server（`firebase serve` 或 `python3 -m http.server`），或直接測線上版
- `week-progress-ufkaq.web.app` 已在 Auth 授權網域預設清單；本地測試用 `localhost` 也預設有效
